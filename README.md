# 食品工厂HACCP控制计划与偏差处置平台

独立React前端工程，采用Fluent UI、Redux Toolkit、RTK Query、React Router、Vite和TypeScript。数据通过浏览器持久化，无需后端。

## 功能

- 生产批次、放行状态、监测点与隔离范围。
- HACCP流程图和控制矩阵，记录关键限值、纠偏措施。
- **监控频率版本化**：每个控制点保存完整频率版本链（频率 + 生效时刻）；改频只追加新版本，只影响生效时刻之后；另设“回填历史”入口供升级前数据补录频率。
- **断档判定**：同一套频率依据同时驱动控制矩阵、批次监测、偏差处置和放行结论。相邻监测读数间隔超过窗口起点当时生效频率即为一段断档；连续记录/每批类频率不做间隔判定。
- **断档联动**：断档窗口自动登记偏差并冻结批次放行；补录读数另记“录入时刻”，与监测时刻分开保存，原有读数永不改动。
- **改频重算**：频率变更后未确认的断档判定自动重算，不成立则撤销偏差（保留撤销原因）；质量人员“确认”后的断档判定固定，不再重算。重复重算按断档窗口签名（批次|控制点|起|止）去重，不重复开偏差。
- **放行唯一依据**：不存在缺频率版本的历史窗口、无未关闭偏差、每个断档窗口之后有合格读数（含补录复检），批次才回到放行流程；偏差复核通过同样要求之后存在合格读数。
- **升级前数据**：历史读数时刻没有任何已生效频率版本时标记“待回填”，先回填再判定；回填后自动补判、登记偏差并冻结。
- 偏差登记、原因与证据调查、返工/报废分支、复核退回和签字。
- 完整版本化审计和JSON追溯包导出。

端口为`18464`。

```bash
npm install
npm run build
npm run dev           # 启动界面
npm run verify:rules  # 命令行验证频率/断档/偏差/放行联动规则（31项）
```
